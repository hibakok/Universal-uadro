CHARTER — КОНСТИТУЦИЯ ПРОЕКТА UNIVERSAL UADRO
=============================================

Неизменные принципы. Менять этот файл можно только осознанно и без
ухудшения любого из пунктов.

1. КИРПИЧИ

Любой метод решает одну задачу и по возможности не длиннее 30 строк
кода. Сложные методы строятся исключительно из более простых, как из
кирпичиков. Если метод разросся — он обязан быть разбит на части.

2. ИЗОЛЯЦИЯ ВЕТВЕЙ

Метод вызывает только методы своей ветви или методы нижних слоёв,
явно перечисленные в его карточке (поле @depends). Скрытые зависимости
запрещены.

3. ПРЕДЕЛ РАЗМЕРА

Один файл — не более 500 строк (CI блокирует нарушение), цель — не
более 200 строк. Один файл — одна ответственность.

4. САМООПИСАНИЕ

Реестр методов (каталог registry/: индекс METHODS.txt + карточки
по исходным файлам, сгруппированные в каталогах ветвей) генерируется
автоматически и обязан быть актуальным (CI регенерирует его при каждом
коммите).

5. СПЕЦИФИКАЦИИ ПРЕЖДЕ КОДА

Каждый слой имеет спецификацию в SPEC/. Код не может противоречить
спецификации; каждое поведение спецификации покрыто тестом.

6. НЕТ СТОРОННИХ БИБЛИОТЕК

Используются только стандартная библиотека бустрап-языка (Python) и код
проекта. Бустрап-инструменты помечаются слоем T*; по мере самохостинга
(когда инструменты начинают писаться на самом uadro) они заменяются
собственными и удаляются.

7. МАЛЫЕ ШАГИ

Одно изменение — одна логическая правка. Каждая правка оставляет
репозиторий работоспособным, тесты — зелёными. Этап закрывается только
при выполнении всех критериев готовности из ROADMAP.txt.

8. НЕ УХУДШАТЬ

Любой рефакторинг сохраняет функциональность. Поведение, закреплённое
спецификацией или тестом, меняется только вместе с ними.

9. ОТКРЫТАЯ ВХОДНАЯ ТОЧКА

Порядок чтения для входа в проект: README.txt -> CHARTER.txt ->
ROADMAP.txt -> DOC/CONTINUE.txt. Читать репозиторий целиком не требуется
и не нужно: реестр методов и спецификации позволяют найти нужную ветвь
за минуты.

10. РАЗДЕЛЕНИЕ ТРУДА

ИИ готовит изменения в своей копии, проверяет их инструментами
репозитория и передаёт человеку полные тексты файлов. Человек применяет
их через веб-интерфейс GitHub и сообщает состояние CI. Следующий шаг
готовится только по факту применённых изменений.

11. ТОЛЬКО .TXT

Файлы Markdown (.md) в проекте запрещены: агентам они нужны как обычный
текст, а при передаче через чаты разметка ломается. Вся документация —
только .txt в кодировке UTF-8. Существующие .md заменяются на .txt.
