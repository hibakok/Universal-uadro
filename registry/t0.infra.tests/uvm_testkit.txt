КАРТОЧКИ ФАЙЛА tests/uvm_testkit.py

Ветвь: t0.infra.tests
Слой: T0
Методов: 13
Генерируется tools/registry_scan.py; вручную не редактировать.
Описание: Общий тест-набор UVM: компактные машины, снимки стека, сборка
          образов программ (в машину и байтами в файл), чтение кодов
          ловушек и остановки, заглушки потоков хоста, прогон образов
          через cli, прогон без процесса с подменёнными stdin/stdout
          (run_with_io) и прогон с сохранением машины (run_saved) — для
          тестов ветвей t0.uvm.* и собственных инструментов Этапа 4
          (SPEC/L4-SELFHOST.txt).

МЕТОД small(ram_size, ds_size, rs_size) -> Machine
  вход:        ram_size: int — размер ОЗУ в байтах (по умолчанию 64)
  вход:        ds_size: int — ёмкость стека данных в словах (по
               умолчанию 8)
  вход:        rs_size: int — ёмкость стека возвратов в словах (по
               умолчанию 4)
  выход:       m: Machine — машина с малым ОЗУ и малыми стеками
  функция:     Компактная машина для быстрых тестов границ и
               переполнений; размеры переопределяются точечно.
  зависимости: uc.Machine

МЕТОД stack_of(m) -> list
  вход:        m: Machine — состояние машины
  выход:       items: list — снимок стека данных (нижний элемент первым)
  функция:     Копия содержимого DS для сравнения в тестах.

МЕТОД trap_code(action) -> int
  вход:        action: callable — действие, обязанное поднять ловушку
  выход:       code: int — код поднятой ловушки
  функция:     Исполняет действие и возвращает код ловушки; без ловушки
               — ошибка теста.
  зависимости: uc.UvmTrap

МЕТОД halt_code(action) -> int
  вход:        action: callable — действие, обязанное поднять UvmHalt
  выход:       code: int — код нормальной остановки
  функция:     Исполняет действие и возвращает код остановки HALT; без
               остановки — ошибка теста.
  зависимости: uc.UvmHalt

МЕТОД imm64(v) -> bytes
  вход:        v: int — слово (оборачивается по модулю 2^64)
  выход:       raw: bytes — 8 байтов little-endian
  функция:     Кодирует поле imm64 инструкции (SPEC, раздел 4); кирпич
               сборки тестовых образов для ветвей t0.uvm.*.
  зависимости: uc.to_word

МЕТОД image_of(parts) -> bytes
  вход:        parts: list — элементы образа: int 0..255 (байт) или
               bytes
  выход:       image: bytes — образ программы
  функция:     Собирает элементы в один образ байтов; кирпич тестов
               ветвей t0.uvm.cli и t0.uvm.integration (запись образа в
               файл).

МЕТОД image_file(image) -> contextmanager
  вход:        image: bytes — образ программы
  выход:       cm: contextmanager — выдаёт путь к временному файлу с
               образом
  функция:     Записывает образ во временный файл; путь действует внутри
               with, файл и каталог удаляются на выходе; кирпич тестов
               ветвей t0.uvm.cli и t0.uvm.integration.
  использует:  tempfile — временный каталог теста

МЕТОД load_prog(m, parts) -> None
  вход:        m: Machine — состояние машины
  вход:        parts: list — элементы образа: int 0..255 (байт) или
               bytes
  выход:       нет
  функция:     Собирает элементы в образ (image_of), загружает его с
               адреса 0 и сбрасывает состояние запуска: PC = 0, стеки
               пусты; кирпич тестов ветвей t0.uvm.decode/exec/run.
  зависимости: uc.load_image, image_of

МЕТОД FakeStream(data)
  вход:        data: bytes — начальные байты (для заглушки ввода)
  выход:       fake: FakeStream — поток с полем buffer
  функция:     Заглушка stdin/stdout: обработчики SYS читают и пишут
               через поле buffer, как у реальных потоков Python; для
               stdout — с contextlib.redirect_stdout, для stdin — с
               patched_stdin.

МЕТОД patched_stdin(stream, action) -> result
  вход:        stream: FakeStream — заглушка стандартного ввода
  вход:        action: callable — проверяемое действие
  выход:       result — значение, возвращённое action (проброс наружу)
  функция:     Подменяет sys.stdin на время действия, гарантированно
               восстанавливает после (в contextlib нет redirect_stdin) и
               возвращает результат действия; кирпич run_with_io.
  использует:  sys.stdin — стандартный ввод хоста (подмена на время
               действия)

МЕТОД run_via_cli(image, args) -> tuple
  вход:        image: bytes — образ программы
  вход:        args: list — дополнительные аргументы после пути (по
               умолчанию
  вход:        пусто)
  выход:       code: int — код завершения cli.main
  выход:       out: bytes — байты, выведенные программой в stdout
  функция:     Полный прогон образа через командный запуск: временный
               файл (image_file), cli.main с подменённым stdout
               (FakeStream); кирпич тестов ветвей t0.uvm.cli и
               t0.uvm.integration.
  использует:  sys.stdout — стандартный вывод хоста (подмена на время
               прогона)
  зависимости: image_file, FakeStream, uvm_cli.main

МЕТОД run_with_io(image, feed) -> tuple
  вход:        image: bytes — образ программы
  вход:        feed: bytes — байты стандартного ввода (по умолчанию
               пусто)
  выход:       code: int — код завершения: imm HALT или код ловушки
  выход:       out: bytes — байты, выведенные программой в stdout
  функция:     Прогон образа без процесса: SYS 0 читает feed, SYS 1
               пишет в выходной буфер (run_image под подменёнными
               stdin/stdout); кирпич золотых тестов собственных
               инструментов Этапа 4 (SPEC/L4-SELFHOST.txt, раздел 6).
  использует:  sys.stdin, sys.stdout — потоки хоста (подмена на время
               прогона)
  зависимости: FakeStream, patched_stdin, uvm_run.run_image

МЕТОД run_saved(image, feed) -> tuple
  вход:        image: bytes — образ программы (инструмента)
  вход:        feed: bytes — байты стандартного ввода (по умолчанию
               пусто)
  выход:       code: int — код завершения: imm HALT или код ловушки
  выход:       out: bytes — байты, выведенные программой в stdout
  выход:       m: Machine — остановленная машина узла (ОЗУ, PC, стеки):
  выход:       снимки читаются после прогона по раскладке инструмента
  функция:     Прогон образа без процесса с сохранением машины (SPEC/
               L4-SELFHOST.txt, раздел 5Б, подшаг 1): как run_with_io,
               но машина не отбрасывается — эмулятор l1.uvm.* хранит
               состояние гостя в фиксированных адресах своей ОЗУ, тесты
               читают их из снимка; машина узла — по умолчанию 1 МиБ
               (инструменту нужно не менее 0x90A80).
  использует:  sys.stdin, sys.stdout — потоки хоста (подмена на время
               прогона)
  зависимости: FakeStream, patched_stdin, uvm_run.run_image
