КАРТОЧКИ ФАЙЛА src/l1/dec.ubrk

Ветвь: l1.uvm.emu
Слой: L1
Методов: 3
Генерируется tools/registry_scan.py; вручную не редактировать.
Описание: Эмулятор UVM — декодер инструкции гостя (SPEC/L4-SELFHOST.txt,
          раздел 5Б, подшаг 2): код — байт по gpc (вне ОЗУ гостя —
          ловушка 7), принадлежность — шесть диапазонов SPEC/L0-UVM.txt
          (неизвестный код — ловушка 6), признак imm64 — слово сравнений
          (как hasimm ассемблера, раздел 5А), поле imm64 — восемь байтов
          LE по gpc + 1; переводит gpc на байт за инструкцией целиком —
          контракт обработчиков (как decode эталона t0.uvm.decode).

МЕТОД inrange ( c -- flag )
  вход:        c: слово — опкод 0..255
  выход:       flag: слово — 1: код принадлежит одному из шести
               диапазонов
  выход:       таблицы опкодов; 0: код вне диапазонов — неизвестный
               опкод
  функция:     Принадлежность кода шести диапазонам SPEC/L0-UVM.txt
               (раздел 5): 0x00-0x07 (стек), 0x10-0x13 (память),
               0x20-0x2C (арифметика), 0x30-0x35 (сравнения), 0x40-0x45
               (переходы), 0x50 (система); внутри диапазонов пустых
               кодов нет; после 0x45 валиден ровно 0x50 — дыры 0x46-0x4F
               и всё выше 0x50 дают 0 (исправлено в подшаге 6: раньше
               хвост «GTU 0x50» принимал 0x46-0x4F как валидные, и это
               маскировала заготовка dsys, останавливавшая всё с кодом
               6); цепочка сравнений с EXIT, как rowbase дизассемблера
               (раздел 5); кирпич decode.
  зависимости: LEU, LTU, EQ, DUP, DROP, IF, EXIT, THEN

МЕТОД hasimm ( code -- flag )
  вход:        code: слово — опкод 0..255
  выход:       flag: слово — 1, если за опкодом следует поле imm64,
               иначе 0
  функция:     Признак поля imm64 без таблицы (SPEC/L4-SELFHOST.txt,
               раздел 5Б: как hasimm раздела 5А): сравнения и диапазоны
               — коды 0x01, 0x07, 0x40-0x43, 0x45, 0x50 (PUSH, PICK,
               JMP, JZ, JNZ, CALL, HALT, SYS — SPEC/L0-UVM.txt, раздел
               5); кирпич decode.
  зависимости: EQ, LTU, LEU, DUP, DROP, IF, EXIT, THEN

МЕТОД decode ( -- )
  вход:        нет (клетка gpc — PC гостя, указывает на байт опкода)
  выход:       нет; gc — код инструкции, gv — imm64 (0 без поля), gpc —
               адрес
  выход:       байта за инструкцией целиком (gpc + 1 либо gpc + 9)
  функция:     Декодирует инструкцию гостя по gpc (SPEC/L4-SELFHOST.txt,
               раздел 5Б; как decode эталона t0.uvm.decode): код —
               gloadbyte по gpc (вне ОЗУ гостя — ловушка 7, STOP с кодом
               7); код вне шести диапазонов — ловушка 6 (STOP с кодом 6,
               gpc не меняется); hasimm — gloadword по gpc + 1 читает
               поле imm64 (ловушка 7 по байтам), иначе gv = 0; gpc
               переводится за инструкцию целиком — контракт
               обработчиков: не-переходы ничего не делают, переходы
               переписывают gpc сами (подшаги 3-6); кирпич dispatch
               (tab.ubrk).
  зависимости: gpcaddr, gloadbyte, gc, inrange, not, STOP, hasimm,
               gloadword,, gv, ADD, STORE64, LOAD64
