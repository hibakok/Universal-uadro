КАРТОЧКИ ФАЙЛА src/l1/mem.ubrk

Ветвь: l1.uvm.emu
Слой: L1
Методов: 17
Генерируется tools/registry_scan.py; вручную не редактировать.
Описание: Эмулятор UVM — память инструмента: use-включение главного
          файла src/l1/emu.ubrk (SPEC/L4-SELFHOST.txt, раздел 5Б,
          подшаги 1-2). Раскладка ОЗУ инструмента — слова-адреса буферов
          и клеток состояния гостя; кирпичи чтения образа гостя из stdin
          (keyok, imgroom, imgput), доступа к памяти гостя по байтам
          (gloadbyte, gloadword — ловушка 7 вне ОЗУ гостя) и начального
          состояния машины гостя (greset). Стеки гостя
          (gpush/gpop/gpick, rpush/ rpop) — подшаг 3; записи в память
          гостя — подшаг 4.

МЕТОД grambase ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x10000, первый байт ОЗУ гостя в ОЗУ
               узла
  функция:     Раскладка ОЗУ (SPEC/L4-SELFHOST.txt, раздел 5Б): ОЗУ
               гостя — 512 КиБ, образ с stdin пишется с адреса гостя 0;
               доступ к памяти гостя — через базу: адрес гостя a ->
               0x10000 + a.

МЕТОД gramlimit ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90000, за последним байтом ОЗУ
               гостя
  функция:     Предел образа гостя в ОЗУ узла: вход длиннее 512 КиБ —
               ловушка 7 гостя до начала исполнения — код 7, вывод пуст
               (раздел 5Б); кирпич imgstep главного файла emu.ubrk.

МЕТОД gramsize ( -- n )
  вход:        нет
  выход:       n: слово — 0x80000, размер ОЗУ гостя в байтах (512 КиБ)
  функция:     Размер ОЗУ гостя: адрес гостя обязан быть меньше gramsize
               прежде сложения с базой — перенос слова при a + grambase
               ошибочно прошёл бы проверку по пределу; кирпич gloadbyte.

МЕТОД gpcaddr ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90A00, клетка gpc — PC гостя

               t0.infra.tests).

  функция:     Раскладка ОЗУ: gdsp хранит число слов в стеке данных

  выход:       addr: слово — адрес 0x90A10, клетка grsp — слов в RS

  функция:     Раскладка ОЗУ: grsp хранит число слов в стеке возвратов

               grsp * 8).

МЕТОД keyok ( -- c 1 | 0 )
  вход:        нет (байт входа читается из stdin, KEY)
  выход:       pair: c и флаг 1 — прочитан байт; либо 0 без байта — EOF
  функция:     Читает байт входа инструмента (KEY): EOF даёт только флаг
               0, байт — c и флаг 1; дубль кирпича keyok ассемблера
               (asmmem.ubrk) — ветви изолированы (CHARTER.txt, п. 2);
               кирпич imgstep главного файла emu.ubrk.
  зависимости: KEY

МЕТОД imgroom ( cur -- flag )
  вход:        cur: слово — адрес узла следующего байта образа гостя
  выход:       flag: слово — 1: байт влезает (cur < gramlimit); 0: ОЗУ
               гостя
  выход:       полно — ловушка 7
  функция:     Проверка ёмкости образа гостя перед записью байта: вход
               сверх 512 КиБ обязан закончиться ловушкой 7 гостя до
               начала исполнения (SPEC/L4-SELFHOST.txt, раздел 5Б);
               кирпич imgstep главного файла emu.ubrk.
  зависимости: gramlimit, LTU

МЕТОД imgput ( cur c -- cur' )
  вход:        cur: слово — адрес узла следующего байта образа гостя
  вход:        c: слово — прочитанный байт входа 0..255
  выход:       cur': слово — адрес узла следующего байта после записи
  функция:     Записывает байт c образа гостя по адресу узла cur
               (STORE8) и возвращает cur + 1; кирпич imgstep главного
               файла emu.ubrk.
  зависимости: OVER, STORE8, ADD

МЕТОД gloadbyte ( a -- b )
  вход:        a: слово — адрес гостя
  выход:       b: слово — байт ОЗУ гостя 0..255
  функция:     Читает байт ОЗУ гостя (SPEC/L4-SELFHOST.txt, раздел 5Б:
               адрес гостя a -> grambase + a): a >= gramsize — ловушка 7
               гостя (STOP, код 7) прежде сложения с базой — перенос
               слова при a + grambase ошибочно прошёл бы проверку по
               пределу; кирпич декодера (dec.ubrk) и обработчиков группы
               «память» (подшаг 4).
  зависимости: gramsize, LTU, not, grambase, ADD, LOAD8, STOP

МЕТОД gwstep ( -- done )
  вход:        нет (клетки gi, gw, ga — состояние чтения слова)
  выход:       done: слово — 0: байт прочитан и накоплен; 1: все восемь
               байтов
  выход:       прочитаны
  функция:     Один шаг чтения слова ОЗУ гостя (как load_word эталона,
               t0.uvm.core): байт по адресу гостя ga + gi — gloadbyte
               (ловушка 7 вне ОЗУ гостя), gw = gw + байт << 8 * gi, gi +
               1; кирпич gloadword.
  зависимости: gi, ga, gloadbyte, gw, MUL, SHL, ADD, STORE64, LOAD64,
               GEU, IF

МЕТОД gloadword ( a -- w )
  вход:        a: слово — адрес гостя младшего байта слова
  выход:       w: слово — 64-битное слово ОЗУ гостя (байты
               little-endian)
  функция:     Читает восемь байтов LE из ОЗУ гостя (проверка каждого
               байта — gloadbyte, ловушка 7): ga = a, gi = 0, gw = 0,
               затем gwstep до готовности; кирпич декодера — поле imm64
               (dec.ubrk) и будущий обработчик LOAD64 (подшаг 4).
  зависимости: ga, gi, gw, gwstep

МЕТОД greset ( -- )
  вход:        нет
  выход:       нет; клетки gpc = 0, gdsp = 0, grsp = 0
  функция:     Начальное состояние машины гостя (SPEC/L0-UVM.txt, раздел
               2: PC = 0, DS и RS пусты) после загрузки образа; кирпич
               main главного файла emu.ubrk.
  зависимости: gpcaddr, gdspaddr, grspaddr, STORE64
