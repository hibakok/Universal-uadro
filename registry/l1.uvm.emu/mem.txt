КАРТОЧКИ ФАЙЛА src/l1/mem.ubrk

Ветвь: l1.uvm.emu
Слой: L1
Методов: 25
Генерируется tools/registry_scan.py; вручную не редактировать.
Описание: Эмулятор UVM — память инструмента: use-включение главного
          файла src/l1/emu.ubrk (SPEC/L4-SELFHOST.txt, раздел 5Б,
          подшаги 1-4). Раскладка ОЗУ инструмента — слова-адреса буферов
          и клеток состояния гостя; кирпичи чтения образа гостя из stdin
          (keyok, imgroom, imgput), доступа к памяти гостя по байтам и
          словам (gloadbyte, gloadword, gstorebyte, gstoreword — ловушка
          7 вне ОЗУ гостя), стеков гостя (gpush/gpop/gpick — ловушки
          2/3, rpush/rpop — ловушки 4/5) и начального состояния машины
          гостя (greset). Обработчикам CALL/RET (подшаг 6) нужны
          rpush/rpop.

МЕТОД grambase ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x10000, первый байт ОЗУ гостя в ОЗУ
               узла
  функция:     Раскладка ОЗУ (SPEC/L4-SELFHOST.txt, раздел 5Б): ОЗУ
               гостя — 512 КиБ, образ с stdin пишется с адреса гостя 0;
               доступ к памяти гостя — через базу: адрес гостя a ->
               0x10000 + a.

МЕТОД gramlimit ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90000, за последним байтом ОЗУ
               гостя
  функция:     Предел образа гостя в ОЗУ узла: вход длиннее 512 КиБ —
               ловушка 7 гостя до начала исполнения — код 7, вывод пуст
               (раздел 5Б); кирпич imgstep главного файла emu.ubrk.

МЕТОД gramsize ( -- n )
  вход:        нет
  выход:       n: слово — 0x80000, размер ОЗУ гостя в байтах (512 КиБ)
  функция:     Размер ОЗУ гостя: адрес гостя обязан быть меньше gramsize
               прежде сложения с базой — перенос слова при a + grambase
               ошибочно прошёл бы проверку по пределу; кирпич gloadbyte.

МЕТОД gdsbase ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90000, первый байт стека данных
               гостя
  функция:     Раскладка ОЗУ: стек данных гостя DS — 256 слов, растёт
               вверх; кирпичи стеков — gpush/gpop/gpick (подшаг 3).

МЕТОД gdslimit ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90800, за последним байтом стека DS
               гостя
  функция:     Раскладка ОЗУ: предел стека данных гостя (256 слов по 8
               байтов); переполнение — ловушка 3 (gpush, подшаг 3).

МЕТОД grsbase ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90800, первый байт стека возвратов
               гостя
  функция:     Раскладка ОЗУ: стек возвратов гостя RS — 64 слова, растёт
               вверх; кирпичи стеков — rpush/rpop (подшаг 3).

МЕТОД grslimit ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90A00, за последним байтом стека RS

  функция:     Раскладка ОЗУ: предел стека возвратов гостя (64 слова по

МЕТОД gpcaddr ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90A00, клетка gpc — PC гостя
  функция:     Раскладка ОЗУ: клетки состояния гостя с 0x90A00; gpc
               хранит счётчик команд гостя, снимок машины читается из
               ОЗУ узла по раскладке (раздел 5Б: тест-кирпич run_saved,
               t0.infra.tests).

МЕТОД gdspaddr ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90A08, клетка gdsp — слов в DS
               гостя
  функция:     Раскладка ОЗУ: gdsp хранит число слов в стеке данных
               гостя (0 — пуст); снимок DS — байты [gdsbase, gdsbase +
               gdsp * 8).

МЕТОД grspaddr ( -- addr )
  вход:        нет
  выход:       addr: слово — адрес 0x90A10, клетка grsp — слов в RS
               гостя
  функция:     Раскладка ОЗУ: grsp хранит число слов в стеке возвратов
               гостя (0 — пуст); снимок RS — байты [grsbase, grsbase +
               grsp * 8).

МЕТОД keyok ( -- c 1 | 0 )
  вход:        нет (байт входа читается из stdin, KEY)
  выход:       pair: c и флаг 1 — прочитан байт; либо 0 без байта — EOF
  функция:     Читает байт входа инструмента (KEY): EOF даёт только флаг
               0, байт — c и флаг 1; дубль кирпича keyok ассемблера
               (asmmem.ubrk) — ветви изолированы (CHARTER.txt, п. 2);
               кирпич imgstep главного файла emu.ubrk.
  зависимости: KEY

МЕТОД imgroom ( cur -- flag )
  вход:        cur: слово — адрес узла следующего байта образа гостя
  выход:       flag: слово — 1: байт влезает (cur < gramlimit); 0: ОЗУ
               гостя
  выход:       полно — ловушка 7
  функция:     Проверка ёмкости образа гостя перед записью байта: вход
               сверх 512 КиБ обязан закончиться ловушкой 7 гостя до
               начала исполнения (SPEC/L4-SELFHOST.txt, раздел 5Б);
               кирпич imgstep главного файла emu.ubrk.
  зависимости: gramlimit, LTU

МЕТОД imgput ( cur c -- cur' )
  вход:        cur: слово — адрес узла следующего байта образа гостя
  вход:        c: слово — прочитанный байт входа 0..255
  выход:       cur': слово — адрес узла следующего байта после записи
  функция:     Записывает байт c образа гостя по адресу узла cur
               (STORE8) и возвращает cur + 1; кирпич imgstep главного
               файла emu.ubrk.
  зависимости: OVER, STORE8, ADD

МЕТОД gloadbyte ( a -- b )
  вход:        a: слово — адрес гостя
  выход:       b: слово — байт ОЗУ гостя 0..255
  функция:     Читает байт ОЗУ гостя (SPEC/L4-SELFHOST.txt, раздел 5Б:
               адрес гостя a -> grambase + a): a >= gramsize — ловушка 7
               гостя (STOP, код 7) прежде сложения с базой — перенос
               слова при a + grambase ошибочно прошёл бы проверку по
               пределу; кирпич декодера (dec.ubrk) и группы «память»
               (opsmem.ubrk, подшаг 4).
  зависимости: gramsize, LTU, not, grambase, ADD, LOAD8, STOP

МЕТОД gwstep ( -- done )
  вход:        нет (клетки gi, gw, ga — состояние чтения слова)
  выход:       done: слово — 0: байт прочитан и накоплен; 1: все восемь
               байтов
  выход:       прочитаны
  функция:     Один шаг чтения слова ОЗУ гостя (как load_word эталона,
               t0.uvm.core): байт по адресу гостя ga + gi — gloadbyte
               (ловушка 7 вне ОЗУ гостя), gw = gw + байт << 8 * gi, gi +
               1; кирпич gloadword.
  зависимости: gi, ga, gloadbyte, gw, MUL, SHL, ADD, STORE64, LOAD64,
               GEU, IF

МЕТОД gloadword ( a -- w )
  вход:        a: слово — адрес гостя младшего байта слова
  выход:       w: слово — 64-битное слово ОЗУ гостя (байты
               little-endian)
  функция:     Читает восемь байтов LE из ОЗУ гостя (проверка каждого
               байта — gloadbyte, ловушка 7): ga = a, gi = 0, gw = 0,
               затем gwstep до готовности; кирпич декодера — поле imm64
               (dec.ubrk) и обработчик LOAD64 (opsmem.ubrk, подшаг 4).
  зависимости: ga, gi, gw, gwstep

МЕТОД gpush ( w -- )
  вход:        w: слово — слово для стека данных гостя
  выход:       нет; слово w лежит в DS гостя, клетка gdsp увеличена на 1
  функция:     Кладёт слово на стек данных гостя (как ds_push эталона,
               t0.uvm.core): стек полон — gdsp не меньше ёмкости из
               раскладки (gdsbase/gdslimit, 256 слов) — ловушка 3 гостя
               (STOP, код 3); слово пишется STORE64 по gdsbase + gdsp *
               8, gdsp + 1; кирпич обработчиков группы «стек»
               (opsstack.ubrk, подшаг 3).
  зависимости: gdspaddr, gdslimit, gdsbase, SUB, UDIV, GEU, IF, DROP,
               STOP,, MUL, ADD, STORE64, LOAD64

МЕТОД gpop ( -- w )
  вход:        нет (клетка gdsp — число слов в DS гостя)
  выход:       w: слово — снятая вершина стека данных гостя
  функция:     Снимает вершину стека данных гостя (как ds_pop эталона):
               пустой стек (gdsp = 0) — ловушка 2 гостя (STOP, код 2);
               gdsp уменьшается на 1, слово читается LOAD64 по gdsbase +
               gdsp * 8; кирпич обработчиков группы «стек» (подшаг 3).
  зависимости: gdspaddr, EQ, IF, STOP, SUB, STORE64, gdsbase, MUL, ADD,,
               LOAD64

МЕТОД gpick ( d -- w )
  вход:        d: слово — глубина элемента (0 — вершина DS гостя)
  выход:       w: слово — копия элемента глубины d; стек гостя не
               меняется
  функция:     Копия элемента глубины d стека данных гостя (как ds_pick
               эталона): d не меньше gdsp (сравнение беззнаковое — imm64
               может быть до 2^64-1) — ловушка 2 гостя; слово читается
               LOAD64 по gdsbase + (gdsp - 1 - d) * 8; кирпич
               обработчиков DUP/OVER/ PICK (подшаг 3).
  зависимости: gdspaddr, DUP, GEU, IF, DROP, STOP, SUB, SWAP, MUL,
               gdsbase,, ADD, LOAD64

МЕТОД rpush ( w -- )
  вход:        w: слово — слово для стека возвратов гостя
  выход:       нет; слово w лежит в RS гостя, клетка grsp увеличена на 1
  функция:     Кладёт слово на стек возвратов гостя (как rs_push
               эталона): стек полон — grsp не меньше ёмкости из
               раскладки (grsbase/ grslimit, 64 слова) — ловушка 5 гостя
               (STOP, код 5); слово пишется STORE64 по grsbase + grsp *
               8, grsp + 1; кирпич обработчика CALL (opsjump.ubrk,
               подшаг 6).
  зависимости: grspaddr, grslimit, grsbase, SUB, UDIV, GEU, IF, DROP,
               STOP,, MUL, ADD, STORE64, LOAD64

МЕТОД rpop ( -- w )
  вход:        нет (клетка grsp — число слов в RS гостя)
  выход:       w: слово — снятая вершина стека возвратов гостя
  функция:     Снимает вершину стека возвратов гостя (как rs_pop
               эталона): пустой стек (grsp = 0) — ловушка 4 гостя (STOP,
               код 4); grsp уменьшается на 1, слово читается LOAD64 по
               grsbase + grsp * 8; кирпич обработчика RET (opsjump.ubrk,
               подшаг 6).
  зависимости: grspaddr, EQ, IF, STOP, SUB, STORE64, grsbase, MUL, ADD,,
               LOAD64

МЕТОД gstorebyte ( addr val -- )
  вход:        addr: слово — адрес гостя (глубже на стеке узла)
  вход:        val: слово — значение; записывается его младший байт
               (вершина)
  выход:       нет; младший байт val в ОЗУ гостя по адресу addr
  функция:     Пишет младший байт val в ОЗУ гостя (как store_byte
               эталона, t0.uvm.core; зеркально gloadbyte): addr не
               меньше gramsize — ловушка 7 гостя (STOP, код 7) прежде
               сложения с базой — перенос слова при addr + grambase
               ошибочно прошёл бы проверку; адрес узла — grambase +
               addr, байт — STORE8; кирпич swstep и обработчик STORE8
               (opsmem.ubrk, подшаг 4).
  зависимости: SWAP, DUP, gramsize, LTU, not, IF, DROP, STOP, grambase,
               ADD,, STORE8

МЕТОД swstep ( -- done )
  вход:        нет (клетки sa, sv, si — состояние записи слова)
  выход:       done: слово — 0: байт записан; 1: все восемь байтов
               записаны
  функция:     Один шаг записи слова в ОЗУ гостя (как store_word
               эталона): адрес гостя sa + si, байт (sv >> 8 * si) AND
               255 — gstorebyte (ловушка 7 вне ОЗУ гостя), si + 1;
               кирпич gstoreword.
  зависимости: sa, si, LOAD64, ADD, sv, MUL, SHR, AND, gstorebyte, GEU,
               IF,, EXIT, STORE64

МЕТОД gstoreword ( addr val -- )
  вход:        addr: слово — адрес гостя младшего байта (глубже на стеке
               узла)
  вход:        val: слово — значение; биты старше 64 игнорируются
               (вершина)
  выход:       нет; восемь байтов val в ОЗУ гостя little-endian по
               адресу addr
  функция:     Раскладывает слово val в восемь байтов LE ОЗУ гостя (как
               store_word эталона): sa = addr, sv = val, si = 0, затем
               swstep до готовности — каждый байт проверен gstorebyte
               (ловушка 7); кирпич обработчика STORE64 (opsmem.ubrk,
               подшаг 4).
  зависимости: SWAP, sa, sv, si, STORE64, swstep, BEGIN, UNTIL

МЕТОД greset ( -- )
  вход:        нет
  выход:       нет; клетки gpc = 0, gdsp = 0, grsp = 0
  функция:     Начальное состояние машины гостя (SPEC/L0-UVM.txt, раздел
               2: PC = 0, DS и RS пусты) после загрузки образа; кирпич
               main главного файла emu.ubrk.
  зависимости: gpcaddr, gdspaddr, grspaddr, STORE64
