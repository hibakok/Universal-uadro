CHARTER — конституция проекта Universal uadro
Неизменные принципы. Менять этот файл можно только осознанно и без ухудшения любого из пунктов.

1. Кирпичи
Любой метод решает одну задачу и по возможности не длиннее 30 строк кода. Сложные методы строятся исключительно из более простых, как из кирпичиков.Если метод разросся — он обязан быть разбит на части.

2. Изоляция ветвей
Метод вызывает только методы своей ветви или методы нижних слоёв, явно перечисленные в его карточке (поле @depends). Скрытые зависимости запрещены.

3. Предел размера
Один файл ≤ 500 строк (CI блокирует нарушение), цель — ≤ 200 строк.Один файл — одна ответственность.

4. Самоописание
Каждый метод снабжён карточкой @method: имя, вход, выход, выполняемая функция. Реестр методов (registry/METHODS.md) генерируется автоматически и обязан быть актуальным (CI проверяет).

5. Спецификации прежде кода
Каждый слой имеет спецификацию в SPEC/. Код не может противоречить спецификации; каждое поведение спецификации покрыто тестом.

6. Нет сторонних библиотек
Используются только стандартная библиотека бустрап-языка (Python) и код проекта. Бустрап-инструменты помечаются слоем T*; по мере самохостинга(когда инструменты начинают писаться на самом uadro) они заменяются собственными и удаляются.

7. Малые шаги
Одно изменение — одна логическая правка. Каждая правка оставляет репозиторий работоспособным, тесты — зелёными. Этап закрывается только при выполнении всех критериев готовности из ROADMAP.md.

8. Не ухудшать
Любой рефакторинг сохраняет функциональность. Поведение, закреплённое спецификацией или тестом, меняется только вместе с ними.

9. Открытая входная точка
Порядок чтения для входа в проект: README.md → CHARTER.md → ROADMAP.md→ DOC/CONTINUE.md. Читать репозиторий целиком не требуется и не нужно:реестр методов и спецификации позволяют найти нужную ветвь за минуты.

10. Разделение труда
ИИ готовит изменения в своей копии, проверяет их инструментами репозитория и передаёт человеку полные тексты файлов. Человек применяет их через веб-интерфейс GitHub и сообщает состояние CI. Следующий шаг готовится только по факту применённых изменений.
