SPEC L2 — UASM v0.1: АССЕМБЛЕР И ДИЗАССЕМБЛЕР UVM
==================================================

Статус: принята 2026-11-05 как основа реализации Этапа 2 (первая
ветвь — t0.uasm.lex; ROADMAP.txt, журнал этапов).
Изменения: только новыми версиями (v0.2, ...) с записью в разделе
«История версий»; реализация и тесты обновляются в том же шаге.

1. НАЗНАЧЕНИЕ
-------------

uAsm — текстовый слой над двоичными образами UVM (SPEC/L0-UVM.txt):

- ассемблер: исходный текст .uasm -> двоичный образ .uvm;
- дизассемблер: образ .uvm -> текст .uasm.

Ассемблер — человекочитаемый способ писать программы UVM до появления
слоя uBrick (Этап 3) и фундамент трансляции машинного кода (Этап 7).

2. СТРУКТУРА ИСХОДНОГО ТЕКСТА
-----------------------------

Текст — строки в кодировке UTF-8. Пробелы и табуляции в начале и конце
строки игнорируются. Строка бывает шести видов:

1) пустая — игнорируется;
2) комментарий — от символа «;» до конца строки; «;» внутри строкового
   литерала в кавычках не начинает комментарий;
3) метка: «имя:» — вся строка целиком (раздел 3);
4) константа: «имя = литерал» — вся строка целиком (раздел 3);
5) директива данных: DB, DW, DS, DZ (раздел 6);
6) инструкция: «МНЕМОНИКА» или «МНЕМОНИКА операнд» (раздел 5).

Один оператор — одна строка. Слова разделяются пробелами и табуляциями;
внутри литералов пробелы значимы.

3. ИМЕНА И СИМВОЛЫ
------------------

Имя: [A-Za-z_][A-Za-z0-9_]* — буква или подчёркивание, затем буквы,
цифры, подчёркивания; только ASCII, регистр значим.

Метка «имя:» (двоеточие примыкает к имени, без пробела) получает
значение — адрес байта следующей записи (инструкции или директивы
данных). Метка в конце текста получает адрес конца образа.

Константа «имя = литерал» получает значение числового литерала
(раздел 4).

Пространство имён одно для меток и констант: два символа с одним
именем — ошибка повторного определения. Имя метки может совпадать
с мнемоникой или именем директивы: роль слова определяет позиция
в строке (раздел 7). Определить константу с именем мнемоники или
директивы нельзя: строка с таким первым словом разбирается как
инструкция.

Использование имени: операнд инструкции, аргумент DB или DW. Ссылки
вперёд разрешены: значения имён собираются первым проходом ассемблера
(раздел 7).

4. ЛИТЕРАЛЫ
-----------

ВИД           ПРИМЕР   ЗАПИСЬ
десятичный    123      [0-9]+
шестнадцатер. 0x1F     0x[0-9A-Fa-f]+ (префикс строчными)
двоичный      0b101    0b[01]+ (префикс строчными)
символьный    'A'      один символ в одинарных кавычках — его код;
                        escape: '\n' '\r' '\t' '\\' '\'' '\0'
строковый     "текст"  двойные кавычки; escape: \n \r \t \\ \" \0;
                        кодируется в байты UTF-8 (для DS/DZ)

Числовой литерал может иметь унарный минус без пробела после него:
-123, -0x10, -'A'. Диапазон числового литерала: -2^63 .. 2^64-1;
значение вне диапазона — ошибка «литерал вне диапазона». При
кодировании отрицательные значения оборачиваются по модулю 2^64
(SPEC/L0-UVM.txt, раздел 1).

5. ИНСТРУКЦИИ
-------------

Мнемоника — заглавными буквами, точно из таблицы опкодов
(SPEC/L0-UVM.txt, раздел 5). Строчная или неизвестная мнемоника —
ошибка «неизвестная мнемоника X».

У опкодов с полем imm64 (PUSH, PICK, JMP, JZ, JNZ, CALL, HALT, SYS)
операнд обязателен; отсутствие — ошибка «нет операнда». У остальных
опкодов операнд запрещён; наличие — ошибка «лишний операнд».

Операнд — числовой литерал или имя; значение имени — слово 0..2^64-1
без оборачивания. У JMP, JZ, JNZ, CALL операнд — абсолютный адрес,
обычно метка.

6. ДИРЕКТИВЫ ДАННЫХ
-------------------

ДИРЕКТИВА  ФОРМАТ            БАЙТЫ
DB         DB v1 [v2 ...]    один байт на аргумент
DW         DW v1 [v2 ...]    восемь байтов little-endian на аргумент
DS         DS "текст"        байты UTF-8 текста
DZ         DZ "текст"        байты UTF-8 текста + байт 0x00

- Аргумент DB — числовой литерал или имя; значение обязано быть
  в 0..255, иначе ошибка «байт вне диапазона».
- Аргумент DW — числовой литерал или имя; значение — слово (диапазон
  литерала из раздела 4), кодируется восемью байтами little-endian.
- Аргумент DS и DZ — ровно один строковый литерал (раздел 4).
- DB и DW требуют хотя бы один аргумент; иначе ошибка «пустая
  директива X».

7. СБОРКА
---------

Ассемблер собирает текст двумя проходами.

Проход 1: строки разбираются в записи (инструкция, директива); каждой
записи назначается адрес; заполняется таблица символов. Размеры
записей: инструкция с imm64 — 9 байтов, без imm64 — 1 байт; DB — 1 байт
на аргумент; DW — 8 байтов на аргумент; DS — длина байтов строки;
DZ — длина + 1.

Проход 2: записи кодируются в байты с подстановкой значений имён.

ПОРЯДОК РАЗБОРА СТРОКИ (после удаления комментария и крайних пробелов;
первое слово строки):

1) слово оканчивается на «:» — метка (раздел 3);
2) слово — мнемоника из таблицы опкодов или директива DB/DW/DS/DZ —
   инструкция или директива данных;
3) в строке вне строковых литералов есть знак «=» — константа
   (раздел 3);
4) иначе — ошибка «неизвестная мнемоника X».

Первая ошибка прекращает сборку. Сообщение об ошибке:

    uAsm: строка N: текст

где N — номер строки текста, начиная с 1. Тексты ошибок:

- «плохое имя» — нарушена форма метки или левой части константы: имя
  не по разделу 3 или после метки «имя:» есть ещё слова;
- «повторное определение имени X»
- «неизвестная мнемоника X» — первое слово строки не метка, не
  мнемоника и не директива, а знака «=» в строке нет;
- «лишний операнд у X» — операнд у инструкции без imm64;
- «нет операнда у X» — отсутствует операнд у инструкции с imm64;
- «плохой литерал X» — операнд инструкции или правая часть константы
  не является литералом по разделу 4;
- «литерал вне диапазона» — числовой литерал вне -2^63 .. 2^64-1;
- «байт вне диапазона» — аргумент DB вне 0..255;
- «неизвестное имя X» — имя использовано, но не определено;
- «пустая директива X» — DB или DW без аргументов;
- «плохой строковый литерал» — аргумент DS/DZ не разобран как
  строковый литерал.

X в сообщении — слово (или остаток строки) из исходного текста. Пустой
текст (ноль записей) собирается в пустой образ.

8. ДИЗАССЕМБЛИРОВАНИЕ
---------------------

Дизассемблер читает образ линейно с адреса 0 и печатает по одной
инструкции на строку: «МНЕМОНИКА» или «МНЕМОНИКА значение»; значения —
десятичные литералы, имена не восстанавливаются.

Признак останова декодирования: неизвестный опкод или поле imm64,
не помещающееся в образ. С этого байта до конца образа данные
печатаются директивами DB — до восьми аргументов на строку. Если образ
закончился на границе инструкции, директив DB нет. Пустой образ
дизассемблируется в пустой текст.

Раунд-трип (критерий готовности Этапа 2): для любого образа B,
дизассемблируемого без ошибок,

    assemble(disasm(B)) == B

9. ФАЙЛЫ И КОМАНДЫ
------------------

Исходники ассемблера — файлы .uasm, образы — .uvm. Команды (ветвь
t0.uasm.cli):

    python tools/uasm_cli.py asm ИСТОЧНИК.uasm ОБРАЗ.uvm
    python tools/uasm_cli.py dis ОБРАЗ.uvm [ТЕКСТ.uasm]

Режим asm собирает текст в образ; режим dis дизассемблирует образ
в файл или, без имени файла, в stdout. Ошибки — код выхода 2
и сообщение в stderr.

10. ВЕТВИ СЛОЯ
--------------

- t0.uasm.lex — кирпичи литералов: числа, символы, имена, строки
- t0.uasm.symbols — таблица символов: имя -> значение
- t0.uasm.line — разбор одной строки в запись
- t0.uasm.encode — кодирование записей в байты
- t0.uasm.assemble — проходы 1 и 2, сборка текста в образ
- t0.uasm.disasm — дизассемблер образа
- t0.uasm.cli — командные режимы asm и dis
- t0.uasm.integration — интеграционные программы на uAsm
