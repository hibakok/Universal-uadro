Это сердце фундамента: точная спецификация виртуального процессора, по которой на следующем шаге будет написан эмулятор.

SPEC L0 — UVM v0.1: универсальная виртуальная машина
Статус: черновик, принимается вместе с Этапом 1 (реализацией-эталоном).Изменения: только новыми версиями (v0.2, ...) с записью в разделе«История версий»; реализация и тесты обновляются в том же шаге.

1. Модель машины
UVM — стековая машина с байтовой адресацией памяти.

Составляющие:

ОЗУ: линейный массив байтов RAM[0 .. size-1]; size задаётся призапуске, по умолчанию 1 МиБ (1048576). Образ программы загружаетсяс адреса 0.
PC — счётчик команд: адрес байта следующей инструкции.
DS — стек данных: массив 64-битных слов, по умолчанию 1024 слова.
RS — стек возвратов: массив 64-битных слов, по умолчанию 256 слов.
Принципы:

Слова — 64-битные целые без знака; переполнения оборачиваютсяпо модулю 2^64.
Порядок байт — little-endian: в полях imm64 инструкций и в LOAD64/STORE64.
Стеки DS и RS — отдельные аппаратные структуры, не отображённые в ОЗУ:доступ к ним возможен только инструкциями. Программная память и стекине пересекаются.
Выравнивание адресов не требуется (в том числе для LOAD64/STORE64).
Исполнение детерминировано, за исключением SYS 0 (чтение ввода).
Обозначение эффекта на стек: ( до -- после ); правый элемент — вершина.

2. Загрузка и запуск
Образ программы (байты) копируется в ОЗУ с адреса 0.
PC = 0; DS и RS пусты.
Инструкции исполняются, пока не встретится HALT или ловушка.
3. Коды завершения и ловушки
Код	Смысл
0	нормальное завершение (HALT imm; пользовательским программам рекомендован imm = 0)
1	деление на ноль
2	опустошение стека данных DS
3	переполнение стека данных DS
4	опустошение стека возвратов RS
5	переполнение стека возвратов RS
6	неизвестный опкод
7	обращение вне ОЗУ
8	неизвестный номер SYS
Ловушка немедленно завершает исполнение с указанным кодом.Пользовательским программам рекомендованы коды 0 и ≥ 16, чтобы не путатьсяс ловушками.

4. Кодировка инструкций
Один байт опкода; у части опкодов за ним следует 8-байтовое поле imm64(little-endian). Адреса JMP/JZ/JNZ/CALL — абсолютные адреса байтов в ОЗУ.При CALL на RS кладётся адрес байта, следующего за полем imm64.

Замечания о минимальности (кирпичи, выводимые из других):

DUP и OVER выводятся из PICK, оставлены для компактности кода.
Знаковые сравнения, знаковые операции и загрузки 16/32-бит не включены:они собираются на слое uBrick из беззнаковых кирпичей (сдвиги, XOR-трюксо знаком).
Логическое отрицание собирается как 0 EQ.
6. Системные вызовы (SYS) v0.1
SYS — временный мост к узлу-хосту до появления шины устройств (Этап 5).

n	Действие
0	прочитать байт из stdin: ( -- c ); c = 0..255 или 0xFFFFFFFFFFFFFFFF при EOF
1	вывести байт в stdout: ( c -- ); выводится c по модулю 256
Неизвестный n → ловушка 8.

7. История версий
v0.1 — первый черновик: модель машины, 37 опкодов, SYS 0/1, ловушки 1–8.
