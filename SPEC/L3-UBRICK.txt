SPEC L3 — UBRICK v0.2: КИРПИЧНЫЙ ЯЗЫК
=====================================

Статус: v0.2 от 2026-11-05 — действующая основа Этапа 3 (закрыты
ветви t0.ubrick.dict и t0.ubrick.parse; ROADMAP.txt, журнал этапов).
Изменения: только новыми версиями (v0.3, ...) с записью в разделе
«История версий»; реализация и тесты обновляются в том же шаге.

1. НАЗНАЧЕНИЕ
-------------

uBrick — слой слов-кирпичей над uAsm (SPEC/L2-UASM.txt):

- программа на uBrick — набор определений слов и данных;
- каждое слово — подпрограмма UVM: примитив — одна инструкция,
  производное — последовательность инструкций и вызовов;
- компилятор uBrick переводит исходник в текст uAsm, образ собирает
  ассемблер uAsm: слои не дублируют работу друг друга.

uBrick — фундамент самохостинга (Этап 4) и языка uLang (Этап 6).

2. МОДЕЛЬ ИСПОЛНЕНИЯ
--------------------

Трансляция подпрограммная.

- Примитив (раздел 4.1) врезается в тело вызвавшего слова: одна
  инструкция UVM на месте обращения.
- Производное слово (раздел 4.2) и слово пользователя — подпрограммы:
  обращение — CALL их метки, выход — RET; тело присутствует в образе
  один раз (раздел 7).
- Обращение вперёд и взаимная рекурсия разрешены: метки разрешает
  проход 1 ассемблера (SPEC/L2-UASM.txt, раздел 7).

Пролог программы (адрес 0):

    CALL main
    HALT 0

Слово main обязательно (раздел 7). Нормальное завершение — код 0:
возврат из main в пролог или слово BYE; аварийные коды — только
ловушки UVM (SPEC/L0-UVM.txt, раздел 3).

Слова работают со стеком данных DS; эффект на стек — в обозначении
( до -- после ), правый элемент — вершина (как в SPEC/L0-UVM.txt).

3. СИНТАКСИС ИСХОДНИКА
----------------------

Исходник — строки UTF-8; пробелы и табуляции в начале и конце строки
игнорируются. Разбор потоковый: тело определения может занимать
несколько строк, перенос строки — разделитель слов.

Виды операторов:

- пустая строка и комментарий (от «;» до конца строки) — игнорируются;
- «: имя ... ;» — определение слова; тело — между именем и «;»;
- «var имя» — переменная (раздел 6), одна строка;
- «text имя "литерал"» — строка данных (раздел 6), одна строка.

Вне определения допустимы только «:», «var» и «text»; иное слово
вне определения — ошибка «слово вне определения X».

Правила «;» (v0.2):

- «;» вне литералов в кавычках обрезает строку: остаток строки —
  комментарий и не разбирается;
- строка, чей первый непробельный символ — «;», — комментарий
  целиком, на любом уровне: между операторами и внутри тела «:»;
- обрезавший строку «;» внутри определения закрывает тело (последнее
  слово определения); вне определения после непустого начала строки
  — ошибка «точка с запятой вне определения»: вне определения
  комментарий пишется только с начала строки;
- «;» внутри литералов в кавычках («';'», «"a;b"») значимым
  не считается.

Имя слова: [a-z][a-z0-9]* — строчная латиница, затем латиница или
цифры; регистр значим. Заглавные буквы, подчёркивания и дефисы
запрещены: заглавными пишутся примитивы и конструкции, подчёркивание
зарезервировано за служебными метками генератора (раздел 7).

Имя определения — первое слово после «:», даже на следующей строке
(перенос строки — разделитель слов); слово-кандидат проверяется
правилами имён, поэтому «: ;» даёт «плохое имя ;». Ключевые слова
операторов var и text (v0.2) входят в список занятых имён (раздел 8);
строчные слова с такими префиксами («var2x») — законные имена.

Тело определения — последовательность слов:

- примитив или конструкция (разделы 4-5);
- числовой литерал: 123, 0x1F, 0b101, 'A', -123 — формы
  SPEC/L2-UASM.txt, раздел 4 (строковые литералы — только в text);
  компилируется в PUSH imm; отрицательные оборачиваются по модулю
  2^64;
- имя определённого слова (включая var/text и производные).

4. СЛОВАРЬ v0.1
---------------

4.1. ПРИМИТИВЫ (тело — одна инструкция UVM)

Мнемоники (29): NOP DROP DUP SWAP OVER ROT LOAD8 LOAD64 STORE8
STORE64 ADD SUB MUL UDIV UMOD NEG SHL SHR SAR AND OR XOR INV EQ NEQ
LTU GTU LEU GEU — имена и семантика по таблице опкодов
(SPEC/L0-UVM.txt, раздел 5).

Псевдонимы (одна инструкция с фиксированным imm):

СЛОВО  КОМПИЛИРУЕТСЯ  ЭФФЕКТ       СЕМАНТИКА
EMIT   SYS 1          ( c -- )     вывести байт c в stdout
KEY    SYS 0          ( -- c )     прочитать байт stdin; 0xFFFF...FF
                                     при EOF
EXIT   RET            ( -- )       выход из слова (возврат)
BYE    HALT 0         ( -- )       завершить программу, код 0

Своего слова PUSH нет: литералы раздела 3 сами транслируются
в PUSH imm. Опкоды управления (JMP JZ JNZ CALL RET HALT SYS) и PICK
словами uBrick не являются: управление потоком — только конструкции
раздела 5, вход и выход — CALL/RET генератора, остановка — пролог
и BYE. Глубина стека в UVM v0.1 читается только константой команды
PICK, поэтому глубокий доступ к DS собирается из SWAP/ROT/DUP/OVER;
вопрос стековой адресации — кандидат в UVM v0.2.

4.2. ПРОИЗВОДНЫЕ СЛОВА (тела — слова uBrick)

Тела производных слов записаны словами uBrick (примитивы, литералы,
конструкции, другие производные слова) и компилируются теми же
кирпичами, что и определения пользователя; в uAsm каждое печатается
один раз (раздел 7). Тесты проверяют поведение, а не байты тел.

СЛОВО    ЭФФЕКТ           СЕМАНТИКА
not      ( ф -- ф' )      логическое отрицание: 0 -> 1, не 0 -> 0
inc      ( a -- a+1 )     увеличение на 1 по модулю 2^64
dec      ( a -- a-1 )     уменьшение на 1
lts      ( a b -- ф )     знаковое a < b (дополнительный код)
les      ( a b -- ф )     знаковое a <= b
gts      ( a b -- ф )     знаковое a > b
ges      ( a b -- ф )     знаковое a >= b
abs      ( a -- |a| )     модуль знакового числа
min      ( a b -- m )     меньшее из двух (знаковое)
max      ( a b -- m )     большее из двух (знаковое)
load16   ( addr -- w )    беззнаковое чтение 16 бит (LE)
load32   ( addr -- w )    беззнаковое чтение 32 бита (LE)
store16  ( val addr -- )  запись младших 16 бит (LE)
store32  ( val addr -- )  запись младших 32 бит (LE)
sext8    ( u -- s )       знак-расширение байта (по биту 7)
sext16   ( u -- s )       знак-расширение 16 бит (по биту 15)
sext32   ( u -- s )       знак-расширение 32 бит (по биту 31)
space    ( -- )           вывести пробел (байт 32)
cr       ( -- )           вывести перевод строки (байт 10)
prints   ( addr -- )      печатать байты с addr до байта 0

Знаковые сравнения собираются из беззнаковых сдвигом биаса: оба
операнда XOR-ятся с 2^63, после чего знак-порядок совпадает
с беззнаковым (кирпич LTU и др.). Тело lts:

    PUSH 0x8000000000000000 XOR
    SWAP PUSH 0x8000000000000000 XOR SWAP LTU

5. УПРАВЛЯЮЩИЕ КОНСТРУКЦИИ
--------------------------

Конструкции допустны только внутри тела «:» и образуют стек
вложенности; закрывающее слово связывается с ближайшей незакрытой
конструкцией.

КОНСТРУКЦИЯ  КОМПИЛЯЦИЯ              ФЛАГ
IF           JZ _Li (вперёд)          снимается с DS: 0 — ложь
ELSE         JMP _Lj; метка _Li тут   (переход), не 0 — истина
THEN         метка _Li (или _Lj) тут
BEGIN        метка _Li тут
UNTIL        JZ _Li (назад)           повтор, пока флаг = 0
AGAIN        JMP _Li (назад)          бесконечный цикл; выход —
                                      EXIT или BYE

Правила связывания:

- ELSE принадлежит открытому IF; второе ELSE того же IF — ошибка
  «ELSE после ELSE»;
- THEN закрывает открытый IF; UNTIL и AGAIN закрывают открытый
  BEGIN; других пар нет, вложенность произвольная;
- к моменту «;» всё закрыто, иначе «незакрытый IF» / «незакрытый
  BEGIN» — первая открытая конструкция (v0.2);
- метки _Li генерирует компилятор (раздел 7).

Пример — тело слова prints (печать Z-строки до байта 0):

    BEGIN DUP LOAD8 DUP 0 EQ IF DROP DROP EXIT THEN
    EMIT 1 ADD AGAIN

6. ДАННЫЕ: VAR И TEXT
---------------------

var имя — определяет слово «имя» с эффектом ( -- addr ): кладёт
адрес своей ячейки — 8 байтов DW 0 в секции данных (раздел 7).
Хранение и чтение — LOAD64/STORE64: 5 x STORE64, x LOAD64.

text имя "литерал" — определяет слово «имя» с эффектом ( -- addr ):
адрес байтов строки; строка хранится директивой DZ (байты UTF-8
литерала + байт 0x00), печать — словом prints (раздел 4.2).

Литерал у text ровно один, формы SPEC/L2-UASM.txt, раздел 4; иначе
ошибка «плохой строковый литерал».

7. ГЕНЕРАЦИЯ UASM
-----------------

Компилятор печатает текст uAsm (SPEC/L2-UASM.txt) в четыре части:

1) пролог: CALL main, HALT 0;
2) производные слова словаря (раздел 4.2) — каждое: метка, тело,
   RET; включаются всегда, исключение неиспользованных — оптимизация
   будущих версий;
3) определения исходника — в порядке появления: метка слова, тело,
   RET; слова var и text — PUSH d_имя, RET;
4) секция данных — в порядке появления: метка d_имя и DW 0 (var)
   или DZ "литерал" (text).

Обращение к слову пользователя и производному — CALL имя. Служебные
метки генератора: _L<n> — конструкции раздела 5, d_<имя> — данные.
Счётчик n общий для программы и растёт монотонно. Имена слов
(раздел 3) не содержат заглавных и подчёркиваний, поэтому коллизий
со служебными метками нет.

Слово main обязательно и одно: отсутствие — ошибка «слово main
обязательно», повтор — «повторное определение слова main».
Возврат из main попадает на HALT 0 пролога.

8. ОШИБКИ
---------

Первая ошибка прекращает компиляцию. Формат:

    uBrick: строка N: текст

N — номер строки, где стоит слово-нарушитель; ошибки конца текста
(«незакрытое определение», «слово main обязательно») получают номер
последней строки, пустой текст — 1.

Порядок ошибок (v0.2): синтаксические и структурные ошибки
прекращают разбор первой по ходу текста; «неизвестное слово»
и «слово main обязательно» назначаются по безошибочному исходнику,
в порядке следования (сначала первое неизвестное слово, затем
main).

Тексты ошибок:

- «плохое имя X» — имя не по разделу 3; X — слово-кандидат после
  «:» или в var/text, в том числе «;» («: ;»);
- «имя занято X» — имя совпало с примитивом, псевдонимом,
  конструкцией или ключевым словом var/text (v0.2);
- «повторное определение слова X» — слово уже определено (включая
  производные словаря, var, text и main);
- «неизвестное слово X» — слово в теле не литерал, не примитив,
  не конструкция и не определённое слово; ссылки вперёд законны,
  проверка идёт по окончании разбора (v0.2);
- «плохой литерал X» — литерал не разбирается формами раздела 3
  (словом может быть только строчное имя, прочие формы, не
  являющиеся литералами, считаются ошибочными литералами);
- «литерал вне диапазона» — вне -2^63 .. 2^64-1;
- «плохой строковый литерал» — у text нет одного строкового
  литерала;
- «var без имени», «text без имени» — пропущено имя;
- «лишние слова после X» — у var/text есть слова сверх имени
  (и литерала);
- «незакрытый IF», «незакрытый BEGIN» — к моменту «;»; сообщается
  первая открытая конструкция (v0.2);
- «незакрытое определение X» (v0.2) — конец текста при открытом
  «:»; X — имя определения либо «без имени», если имя ещё не
  прочитано;
- «THEN без IF», «ELSE без IF», «ELSE после ELSE»;
- «UNTIL без BEGIN», «AGAIN без BEGIN»;
- «конструкция вне определения» — IF/ELSE/THEN/BEGIN/UNTIL/AGAIN
  вне тела «:»;
- «двоеточие внутри определения», «точка с запятой вне
  определения», «var внутри определения», «text внутри
  определения»;
- «слово вне определения X» — на верхнем уровне слово не «:»,
  не var и не text;
- «слово main обязательно» — main не определён словом «:»
  (var main его не заменяет).

9. ФАЙЛЫ И КОМАНДЫ
------------------

Исходники uBrick — файлы .ubrk (src/). Команда (ветвь
t0.ubrick.cli):

    python tools/ubrick_cli.py compile ИСТОЧНИК.ubrk ОБРАЗ.uvm
        [--asm ТЕКСТ.uasm]

Режим compile переводит исходник в текст uAsm, собирает образ
ассемблером uAsm (ветвь t0.uasm.assemble) и записывает ОБРАЗ.uvm;
--asm дополнительно сохраняет промежуточный текст uAsm. Ошибки —
код выхода 2 и сообщение в stderr.

10. ВЕТВИ СЛОЯ
--------------

- t0.ubrick.dict — словарь uBrick: примитивы (имя -> инструкция
  uAsm), производные (имя -> тело словами uBrick), поиск и списки
- t0.ubrick.parse — разбор исходника в записи: определения, var,
  text, слова и литералы (кирпичи литералов — t0.uasm.lex)
- t0.ubrick.compile — компиляция определения в строки uAsm: тела
  слов, конструкции раздела 5, метки _L<n>
- t0.ubrick.build — сборка программы: пролог, словарь, определения,
  секция данных; вызов t0.uasm.assemble
- t0.ubrick.cli — режим compile
- t0.ubrick.integration — интеграционные программы .ubrk в src/
