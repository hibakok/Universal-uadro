1. МОДЕЛЬ МАШИНЫ
----------------

UVM — стековая машина с байтовой адресацией памяти.

Составляющие:

- ОЗУ: линейный массив байтов RAM[0 .. size-1]; size задаётся при
  запуске, по умолчанию 1 МиБ (1048576). Образ программы загружается
  с адреса 0.
- PC — счётчик команд: адрес байта следующей инструкции.
- CYC — счётчик шагов: 64-битное слово; увеличивается на 1
  в начале каждого шага, до декодирования инструкции; переносится
  по модулю 2^64. Значение читается портом TMR_CYC (раздел 6А).
  Введён v0.3.
- DS — стек данных: массив 64-битных слов, по умолчанию 1024 слова.
- RS — стек возвратов: массив 64-битных слов, по умолчанию 256 слов.
- Шина устройств: таблица «порт -> устройство», привязываемая
  к машине раннером до запуска (раздел 6А). Введена v0.3.

Принципы:

- Слова — 64-битные целые без знака; переполнения оборачиваются
  по модулю 2^64.
- Порядок байт — little-endian: в полях imm64 инструкций и в
  LOAD64/STORE64.
- Стеки DS и RS — отдельные аппаратные структуры, не отображённые
  в ОЗУ: доступ к ним возможен только инструкциями. Программная
  память и стеки не пересекаются.
- Выравнивание адресов не требуется (в том числе для LOAD64/STORE64).
- Исполнение детерминировано, за исключением SYS 0 (чтение ввода)
  и порта TMR_WALL шины устройств (время узла-хоста, раздел 6А).

Обозначение эффекта на стек: ( до -- после ); правый элемент — вершина.

2. ЗАГРУЗКА И ЗАПУСК
--------------------

1. Образ программы (байты) копируется в ОЗУ с адреса 0.
2. PC = 0; CYC = 0; DS и RS пусты.
3. Раннер привязывает шину устройств (раздел 6А): стандартный
   набор — консоль и таймер; блочное хранилище — решение раннера.
4. Инструкции исполняются, пока не встретится HALT или ловушка.

3. КОДЫ ЗАВЕРШЕНИЯ И ЛОВУШКИ
----------------------------

КОД  СМЫСЛ
0    нормальное завершение (HALT imm; пользовательским программам
     рекомендован imm = 0)
1    деление на ноль
2    опустошение стека данных DS
3    переполнение стека данных DS
4    опустошение стека возвратов RS
5    переполнение стека возвратов RS
6    неизвестный опкод
7    обращение вне ОЗУ
8    неизвестный номер SYS
9    отказ устройства: машина без шины, порт не привязан или
     операция запрещена направлением регистра (раздел 6А) — v0.3

Ловушка немедленно завершает исполнение с указанным кодом.
Пользовательским программам рекомендованы коды 0 и >= 16, чтобы не
путаться с ловушками.

4. КОДИРОВКА ИНСТРУКЦИЙ
-----------------------

Один байт опкода; у части опкодов за ним следует 8-байтовое поле imm64
(little-endian). Адреса JMP/JZ/JNZ/CALL — абсолютные адреса байтов
в ОЗУ. При CALL на RS кладётся адрес байта, следующего за полем imm64.

5. ТАБЛИЦА ОПКОДОВ (v0.1; DEVRD/DEVWR — v0.3)
-----------------------------------------------

КОД  МНЕМОНИКА  ФОРМАТ  ЭФФЕКТ                  СЕМАНТИКА
00   NOP        —       ( — )                   ничего не делать
01   PUSH imm   +imm64  ( — imm )               положить константу

                                                верхних
05   OVER       —       ( a b — a b a )         копия второго сверху
06   ROT        —       ( a b c — b c a )       циклический сдвиг
                                                тройки

                                                imm (0 = DUP, 1 = OVER)
10   LOAD8      —       ( addr — u8 )           прочитать байт
                                                (расширяется нулями)

25   NEG        —       ( a — 0-a )             арифметическое

27   SHR        —       ( a n — a>>n )          логический сдвиг вправо
28   SAR        —       ( a n — a>>n )          арифметический сдвиг
                                                вправо (по знаку)
29   AND        —       ( a b — a&b )           побитовое И
2A   OR         —       ( a b — a|b )           побитовое ИЛИ
2B   XOR        —       ( a b — a^b )           побитовая исключающее
                                                ИЛИ
2C   INV        —       ( a — ~a )              побитовая инверсия
30   EQ         —       ( a b — ф )             ф = 1, если a = b,
                                                иначе 0
31   NEQ        —       ( a b — ф )             ф = 1, если a <> b
32   LTU        —       ( a b — ф )             беззнаковое a < b
33   GTU        —       ( a b — ф )             беззнаковое a > b
34   LEU        —       ( a b — ф )             беззнаковое a <= b
35   GEU        —       ( a b — ф )             беззнаковое a >= b
40   JMP addr   +imm64  ( — )                   PC = addr
41   JZ addr    +imm64  ( c — )                 PC = addr, если c = 0
42   JNZ addr   +imm64  ( c — )                 PC = addr, если c <> 0
43   CALL addr  +imm64  ( — )                   адрес возврата -> RS;

44   RET        —       ( — )                   PC <- RS

                                                по модулю 256

                                                узла-хоста

                                                шины устройств (6А.2)
53   DEVWR      —       ( w порт -- )           записать слово в порт
                                                шины устройств (6А.2)

Неиспользуемые коды опкодов — ловушка 6. Коды 0x51 и 0xFF остаются
свободными: золотые наборы дизассемблеров используют их как
неизвестные (tests/test_l2_disasm_gold.py). Инструкции DEVRD (0x52)
и DEVWR (0x53) введены v0.3 (раздел 6А.2) и приняты в таблицу
подшагом 5.2 Этапа 5 (2026-11-06): таблица — 40 записей. Собственные
инструменты Этапа 4 (l1.uvm.*, l2.uasm.*) остаются на 38 записях
v0.2 до подшага 5.4 — их золотые наборы берут опкоды кирпичом
isa_v02_table (tests/uvm_testkit.py).

Замечания о минимальности (кирпичи, выводимые из других):

- DUP и OVER выводятся из PICK, оставлены для компактности кода.
- Знаковые сравнения, знаковые операции и загрузки 16/32-бит не
  включены: они собираются на слое uBrick из беззнаковых кирпичей
  (сдвиги, XOR-трюк со знаком).
- Логическое отрицание собирается как «0 EQ».

6. СИСТЕМНЫЕ ВЫЗОВЫ (SYS) v0.2
------------------------------

SYS — временный мост к узлу-хосту до появления шины устройств
(Этап 5).

n    ДЕЙСТВИЕ
0    прочитать байт из stdin: ( — c ); c = 0..255 или 0xFFFFFFFFFFFFFFFF
     при EOF
1    вывести байт в stdout: ( c — ); выводится c по модулю 256
2    завершить исполнение: ( c — ); код завершения = c по модулю 256 —
     нормальная остановка, как HALT imm, но код берётся со стека
     данных; c снимается прежде остановки, пустой стек — ловушка 2

Неизвестный n — ловушка 8. SYS 0/1 остаются, пока живы инструменты
Этапа 4 (SPEC/L4-SELFHOST.txt); решение о снятии SYS — вместе
с закрытием Этапа 5 (раздел 6А.4).

6А. ШИНА УСТРОЙСТВ (ЧЕРНОВИК v0.3, ЭТАП 5)
------------------------------------------

6А.1. МОДЕЛЬ

Шина — таблица «порт -> устройство». Порт — 64-битное слово; его
значение выбирает регистр устройства. Обращение переносит одно
слово:

- чтение порта: ( — w ) — шина спрашивает устройство;
- запись порта: ( w — ) — шина передаёт слово устройству.

Слово шины — 64-битное слово по модулю 2^64 (как DS). Отказ
устройства — ловушка 9: машина без шины, порт не привязан или
операция запрещена направлением регистра. Привязка устройства
к занятому порту заменяет прежнее устройство на этом порту.

6А.2. ИНСТРУКЦИИ DEV (приняты подшагом 5.2)

КОД  МНЕМОНИКА  ФОРМАТ  ЭФФЕКТ         СЕМАНТИКА
52   DEVRD      —       ( порт -- w )  прочитать слово порта; порт
                                        снимается, слово w кладётся
53   DEVWR      —       ( w порт -- )  записать слово w в порт; w —
                                        глубже, порт — вершина (как
                                        STORE8/STORE64)

Обе инструкции без поля imm64. Операнды снимаются со стека прежде
обращения к шине: пустой стек — ловушка 2 до обращения. Отказ
устройства — ловушка 9 после снятия операндов.

6А.3. КАРТА ПОРТОВ v1

Диапазоны: 0x00-0x0F — консоль, 0x10-0x1F — таймер, 0x20-0x2F —
блочное хранилище. Прочие порты — будущие устройства.

ПОРТ  ИМЯ       НАПРАВЛ.  СЕМАНТИКА
0x00  CON_RX    чтение   байт ввода узла-хоста 0..255; в конце
                                 ввода — слово из всех единиц
0x01  CON_TX    запись   младший байт слова — в вывод узла-хоста
0x10  TMR_CYC   чтение   текущее значение CYC (раздел 1)
0x11  TMR_WALL  чтение   миллисекунды монотонных часов узла-хоста
                                 от точки нуля раннера
0x20  BLK_ADDR  чтение/  окно данных устройства в байтах; чтение
                запись    возвращает окно, запись устанавливает
0x21  BLK_DATA  чтение   слово (8 байтов LE) в окне; после чтения
                                 окно переносится на 8 вперёд; за
                                 концом данных читаются нули
0x22  BLK_SIZE  чтение   размер данных устройства в байтах

Регистры направления: запись в регистр чтения и чтение регистра
записи — ловушка 9. Порты 0x0F, 0x1F, 0x2F — контрольно-статусные
регистры устройств: кандидаты v0.4 (прерывания), в v0.3 не привязаны
(ловушка 9).

6А.4. КОНТРАКТ УСТРОЙСТВ И РАННЕРОВ

- Устройство — пара операций над машиной: read(m, порт) -> слово
  и write(m, порт, слово). Состояние устройство хранит само;
  таймеру нужен CYC — он читает счётчик шагов машины.
- Стандартный набор раннера — консоль и таймер; раннер привязывает
  его до запуска: программа рассчитывает на консоль и таймер
  всегда. Блочное хранилище подключает раннер по своему решению
  (флаг командной строки — подшаг 5.5, ROADMAP.txt).
- Мост узла-хоста (stdin/stdout) — общие кирпичи раннера; в эталоне
  это host_read_byte/host_write_byte (ветвь t0.uvm.ops): консоль шины
  и SYS 0/1 работают через них, пока SYS жив.
- Вложенный раннер (собственный эмулятор на UVM): его узел-хост —
  машина внешнего уровня. Консоль вложенной машины — мост SYS 0/1
  внешнего уровня; TMR_WALL — время внешнего узла; CYC — счётчик
  шагов эмулятора о его госте. Контракт рекурсивен до внешнего
  раннера.
- Данные блочного хранилища — копия байтов, переданная при привязке:
  изменение источника после привязки не видно устройству. В v0.3
  хранилище только читается; запись — кандидат v0.4.
