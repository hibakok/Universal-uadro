# ARCHITECTURE — слои и ветви

## Слои (снизу вверх)

| Слой | Код | Что это | Статус |
|------|-----|---------|--------|
| Спецификации | SPEC | точные текстовые спецификации слоёв | есть |
| Бустрап-инструменты | T0 | Python-инструменты, временные «леса» | T0 есть |
| Двоичный слой | L1 | опкоды UVM, двоичные образы | спецификация готова |
| Ассемблер | L2 | uAsm: мнемоники ⇄ биты | план (Этап 2) |
| Кирпичный язык | L3 | uBrick: слова-кирпичи | план (Этап 3) |
| Язык высокого уровня | L4 | uLang | план (Этап 6) |
| Библиотеки и приложения | L5+ | uStd, графика, игра | план |

## Правила зависимостей

- Слой может использовать только нижележащие слои.
- Код слоёв L* не использует T*-инструменты (те лишь строят и проверяют
  слои L*).
- T*-инструменты временные: при самохостинге заменяются на собственные
  и удаляются.

## Ветви кода

Ветвь — дерево вызовов одного метода: сложный метод состоит из менее
сложных, те — из ещё более простых, и так до предела простоты.

Имя ветви: `<слой>.<подсистема>.<модуль>`, например `t0.infra.registry`;
будущие: `t0.uvm.core` (Python-эталон UVM, Этап 1), `l2.asm.parser`.

Свойства ветвей:

- изоляция: ветвь не обращается к внутренностям чужих ветвей, только
  к их опубликованным методам, описанным карточками;
- локальность: чтобы изменить одно место кода, достаточно прочитать
  карточки методов одной ветви (см. `registry/`) и спецификацию её
  слоя;
- явность: зависимости метода перечислены в карточке (`@depends`).

Замечание о двойных воплощениях: Python-эталон UVM живёт в ветвях
`t0.uvm.*`; при самохостинге (Этап 4) те же подсистемы будут переписаны
на собственном коде и получат ветви `l1.uvm.*`.

## Размещение в репозитории

| Каталог | Содержимое |
|---------|------------|
| `SPEC/` | спецификации слоёв, по одному файлу на слой |
| `DOC/` | карта документов: архитектура, конвенции, протокол продолжения |
| `tools/` | бустрап-инструменты (T0): реестр, проверки, будущие эмулятор и ассемблер |
| `src/` | код слоёв L2+ (появится с Этапа 2) |
| `tests/` | тесты; тесты ветви живут в её файлах `test_*.py` (первая ветвь: t0.infra.registry) |
| `registry/` | генерируемый реестр: индекс `METHODS.md` + карточки по исходным файлам `registry/<ветвь>/<файл>.md` |
