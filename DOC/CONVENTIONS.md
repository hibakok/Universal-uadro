CONVENTIONS — конвенции кода и карточек
Формат файлов
Кодировка UTF-8, переводы строк LF.
Один файл ≤ 500 строк (CI), цель — ≤ 200. Одна ответственность на файл.
Имена файлов: snake_case.py; тесты — test_<модуль>.py.
Идентификаторы в коде — латиницей; описания и документация — по-русски.
Шапка файла (обязательна для каждого файла с кодом)
# @uadro# @file    tools/registry_scan.py# @layer   T0# @branch  t0.infra.registry# @desc    Одна строка описания файла.
@layer — код слоя из DOC/ARCHITECTURE.md (T0, будущие L1, L2, ...).
@branch — имя ветви <слой>.<подсистема>.<модуль>.
@desc — может повторяться: несколько строк описания.
Строки шапки идут подряд в начале файла, до любого другого текста.
Карточка метода (обязательна для каждой функции/метода)
# @method divide(a, b) -> int# @in    a: int — делимое# @in    b: int — делитель, не 0# @out   q: int — частное# @does  Целочисленное деление без остатка.# @uses  глобальное состояние (если метод его трогает)# @depends parse_int, check_zero
@method — имя метода с сигнатурой.
@in — вход: имя, тип, смысл; может повторяться.
@out — выход: имя, тип, смысл; может повторяться.
@does — функция метода; может повторяться (несколько фраз).
@uses — необязательно: используемое глобальное состояние.
@depends — необязательно: методы, которые вызывает данный (изоляцияветвей, см. CHARTER.md, п. 2).
Карточка пишется строками # @... непосредственно над определениемметода, без пустых строк внутри карточки.Всё, что не описано карточкой, не является частью контракта метода.

Правила кирпичей
Метод ≤ ~30 строк, одна задача, одна причина для изменения.
Сложное = композиция простых; новые кирпичи предпочитаются новыммонолитам.
Метод не читает и не пишет глобальное состояние, кроме явно указанногов @uses.
Реестр методов
Реестр генерируется tools/registry_scan.py и обновляется CIавтоматически при каждом коммите; вручную не редактируетсяи не вставляется.
registry/METHODS.md — компактный индекс: ветви, их файлы, число методов.
registry/<ветвь>.md — карточки методов одной ветви (вход / выход /функция / зависимости).
Реестр растёт по ветвям, а не одним файлом, поэтому не упираетсяв лимит строк при росте проекта.
Сейчас сканируются только *.py; с появлением uAsm/uBrick сканеррасширится на их синтаксис комментариев.
Тесты
Тест — это тоже кирпич: один файл тестов покрывает одну ветвь.
Тест обязан быть детерминированным (кроме случаев явной пометки).
Каждое поведение спецификации покрыто хотя бы одним тестом.
Запуск всех тестов из корня репозитория:python -m unittest discover -s tests -t . -v (CI делает то же).
