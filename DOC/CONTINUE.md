# CONTINUE — протокол продолжения проекта

Этот файл — входная точка для любого агента (ИИ или человека), который
продолжает проект без знания всей его истории.

## Порядок входа (несколько минут)

1. `README.md` → что это за проект.
2. `CHARTER.md` → что нельзя нарушать.
3. `ROADMAP.md` → текущий этап и следующий малый шаг
   (раздел «Где мы сейчас»).
4. `registry/METHODS.md` → найти нужную ветвь по имени файла или ветви.
5. Спецификация слоя из `SPEC/` → точный контракт слоёв, которых касается
   изменение.

## Правила работы

- **Не читать репозиторий целиком.** Читать только карточки методов нужной
  ветви и спецификацию её слоя.
- Одно изменение = одна ветвь (или пара «ветвь + её тест»).
- Изменение готовится в отдельной копии, проверяется инструментами
  (`python tools/check_limits.py`, `python tools/registry_scan.py`, тесты
  ветви), затем передаётся человеку для применения через веб-интерфейс
  GitHub полными текстами файлов.
- После применения человек сообщает состояние CI (вкладка Actions).

## Обязанности каждого шага

1. Оставить CI зелёным.
2. Реестр методов CI обновляет сам: убедиться, что после шага появился коммит
   «ci: регенерация реестра методов» (или реестр не изменился).
3. При изменении поведения — обновить спецификацию и тесты.
4. При закрытии/начале этапа — обновить раздел «Где мы сейчас» и журнал
   этапов в `ROADMAP.md`.
5. Ни одного файла длиннее 500 строк.

## Если документы расходятся

Истина в порядке убывания приоритета: спецификация слоя → карточки методов →
тесты → остальная документация. Конфликт фиксируется в пользу старшего
источника, младший исправляется в том же шаге.

## Формат обмена «ИИ ↔ человек»

- ИИ выдаёт: список файлов (путь, действие: создать/заменить) и полное
  содержимое каждого.
- Человек копирует содержимое файлов только из кода-блоков сообщения
  (кнопка копирования), никогда из отрендеренного вида: при копировании
  из отрендеренного вида markdown теряет заголовки, списки и таблицы.
- После вставки человек открывает файл на GitHub и убеждается, что тот
  отрендерился: заголовки крупные, таблицы — таблицами, списки — списками.
  Сплошной текст абзацами означает неудачную вставку — повторить.
- Человек применяет и отвечает состоянием CI плюс любые отклонения
  (например, сообщение об ошибке из Actions).
- Следующий шаг готовится только по фактически применённым изменениям.
