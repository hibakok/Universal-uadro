CONTINUE — протокол продолжения проекта
Этот файл — входная точка для любого агента (ИИ или человека), которыйпродолжает проект без знания всей его истории.

Порядок входа (несколько минут)
README.md → что это за проект.
CHARTER.md → что нельзя нарушать.
ROADMAP.md → текущий этап и следующий малый шаг (раздел«Где мы сейчас»).
registry/METHODS.md (индекс) → найти нужную ветвь по имени файла иливетви; карточки её методов — в registry/<ветвь>.md.
Спецификация слоя из SPEC/ → точный контракт слоёв, которых касаетсяизменение.
Правила работы
Не читать репозиторий целиком. Читать только карточки методов нужнойветви (registry/) и спецификацию её слоя.
Одно изменение = одна ветвь (или пара «ветвь + её тест»).
Изменение готовится в отдельной копии, проверяется инструментами(python tools/check_limits.py; python -m unittest discover -s tests -t . -v;python tools/registry_scan.py), затем передаётся человеку для применениячерез веб-интерфейс GitHub полными текстами файлов.
После применения человек сообщает состояние CI (вкладка Actions).
Обязанности каждого шага
Оставить CI зелёным.
Реестр методов CI обновляет сам: убедиться, что после шага появилсякоммит «ci: регенерация реестра методов» (или реестр не изменился).
При изменении поведения — обновить спецификацию и тесты.
При закрытии/начале этапа — обновить раздел «Где мы сейчас» и журналэтапов в ROADMAP.md.
Ни одного файла длиннее 500 строк.
Если документы расходятся
Истина в порядке убывания приоритета: спецификация слоя → карточкиметодов → тесты → остальная документация. Конфликт фиксируется в пользустаршего источника, младший исправляется в том же шаге.

Формат обмена «ИИ ↔ человек»
ИИ выдаёт: список файлов (путь, действие: создать/заменить/точечнопоправить) и полное содержимое каждого (для точечных правок — старуюи новую строку).
Человек копирует содержимое файлов только из код-блоков сообщения(кнопка копирования), никогда из отрендеренного вида: при копированиииз отрендеренного вида markdown теряет заголовки, списки и таблицы.
После вставки человек открывает файл на GitHub и убеждается, что тототрендерился: заголовки крупные, таблицы — таблицами, списки —списками. Сплошной текст абзацами означает неудачную вставку —повторить.
Человек применяет и отвечает состоянием CI плюс любые отклонения(например, сообщение об ошибке из Actions).
Следующий шаг готовится только по фактически применённым изменениям.
