CONVENTIONS — КОНВЕНЦИИ КОДА И КАРТОЧЕК
=======================================

ФОРМАТ ФАЙЛОВ

- Кодировка UTF-8, переводы строк LF.
- Файлы .md (Markdown) запрещены: вся документация и реестр — только
  .txt простым текстом. Заголовки разделов — ЗАГЛАВНЫМИ буквами,
  таблицы — выровненными колонками моноширинного текста, списки —
  строками с «- » или нумерацией.
- Один файл — не более 500 строк (CI), цель — не более 200. Одна
  ответственность на файл.
- Имена файлов: snake_case.py; тесты — test_<модуль>.py.
- Идентификаторы в коде — латиницей; описания и документация —
  по-русски.

ШАПКА ФАЙЛА (обязательна для каждого файла с кодом)

Пример шапки:

    # @uadro
    # @file    tools/registry_scan.py
    # @layer   T0
    # @branch  t0.infra.registry
    # @desc    Одна строка описания файла.

- @layer — код слоя из DOC/ARCHITECTURE.txt (T0, будущие L1, L2, ...).
- @branch — имя ветви <слой>.<подсистема>.<модуль>.
- @desc — может повторяться: несколько строк описания.
- Строки шапки идут подряд в начале файла, до любого другого текста.

КАРТОЧКА МЕТОДА (обязательна для каждой функции/метода)

Пример карточки:

    # @method divide(a, b) -> int
    # @in    a: int — делимое
    # @in    b: int — делитель, не 0
    # @out   q: int — частное
    # @does  Целочисленное деление без остатка.
    # @uses  глобальное состояние (если метод его трогает)
    # @depends parse_int, check_zero

- @method — имя метода с сигнатурой.
- @in — вход: имя, тип, смысл; может повторяться.
- @out — выход: имя, тип, смысл; может повторяться.
- @does — функция метода; может повторяться (несколько фраз).
- @uses — необязательно: используемое глобальное состояние.
- @depends — необязательно: методы, которые вызывает данный (изоляция
  ветвей, см. CHARTER.txt, п. 2).
- Карточка пишется строками «# @...» непосредственно над определением
  метода, без пустых строк внутри карточки.
- Всё, что не описано карточкой, не является частью контракта метода.

ПРАВИЛА КИРПИЧЕЙ

- Метод — не длиннее ~30 строк, одна задача, одна причина для
  изменения.
- Сложное = композиция простых; новые кирпичи предпочитаются новым
  монолитам.
- Метод не читает и не пишет глобальное состояние, кроме явно
  указанного в @uses.

РЕЕСТР МЕТОДОВ

- Реестр генерируется tools/registry_scan.py и обновляется CI
  автоматически при каждом коммите; вручную не редактируется
  и не вставляется.
- registry/METHODS.txt — компактный индекс: ветви, их файлы, число
  методов.
- registry/<ветвь>/<файл>.txt — карточки методов одного исходного
  файла (вход / выход / функция / зависимости).
- Карточки лежат по исходным файлам: файл карточек не растёт вместе
  с ветвью и не упирается в лимит строк при росте проекта.
- Сейчас сканируются только *.py; с появлением uAsm/uBrick сканер
  расширится на их синтаксис комментариев.

ТЕСТЫ

- Тест — это тоже кирпич: файл тестов покрывает одну ветвь или её
  часть (крупная ветвь делится на несколько файлов тестов).
- Тест обязан быть детерминированным (кроме случаев явной пометки).
- Каждое поведение спецификации покрыто хотя бы одним тестом.
- Запуск всех тестов из корня репозитория:
  python -m unittest discover -s tests -t . -v (CI делает то же).
