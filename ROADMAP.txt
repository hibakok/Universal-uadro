ROADMAP — ЭТАПЫ ПРОЕКТА
=======================

Правила движения: этап закрывается только при выполнении всех критериев
готовности (DoD); CI зелёный; реестр методов актуален. Один рабочий
сеанс — один малый шаг (обычно одна-две ветви кода).

ЭТАП 0 — ИНФРАСТРУКТУРА ИССЛЕДОВАНИЯ (закрыт 2026-11-03)

Что: конституция, дорожная карта, конвенции карточек, реестр методов
с генератором, CI-стражи (лимит строк, тесты, актуальность реестра),
спецификация UVM v0.1.

DoD: все файлы инфраструктуры закоммичены; workflow ci зелёный
и запускает тесты; реестр сгенерирован и актуален.

ЭТАП 1 — ЯДРО UVM v0.1 (ВИРТУАЛЬНЫЙ ПРОЦЕССОР + ОЗУ) (закрыт 2026-11-04)

Что: эмулятор UVM на Python по SPEC/L0-UVM.txt, собранный из кирпичиков.

Ветви этапа (каждая со своим тестом):

- t0.uvm.core — состояние машины, ловушки, ОЗУ, стеки DS/RS
- t0.uvm.ops — обработчики всех опкодов, по файлу на группу (стек,
  память, арифметика, сравнения, переходы, SYS)
- t0.uvm.table — таблица опкодов: код <-> мнемоника, обработчик, imm
- t0.uvm.decode — декодер инструкции по PC
- t0.uvm.exec — шаг исполнения
- t0.uvm.run — цикл запуска; ловушка -> код завершения
- t0.uvm.cli — запуск образа из файла
- интеграционные программы: «вывод символа», арифметика, вложенные
  CALL/RET

DoD: исполняются программы «вывод символа», арифметика, вложенные
вызовы CALL/RET; тесты на каждую группу опкодов и каждую ловушку;
CI зелёный.

ЭТАП 2 — UASM: АССЕМБЛЕР И ДИЗАССЕМБЛЕР

Что: текстовые мнемоники <-> двоичный образ UVM; метки, именованные
константы, директивы данных.

DoD: полный round-trip asm -> bin -> disasm -> asm совпадает; тесты
синтаксических ошибок; в CI собираются и исполняются тестовые
программы.

ЭТАП 3 — UBRICK: КИРПИЧНЫЙ ЯЗЫК

Что: словарь слов-кирпичей, компиляция слов в код UVM; управляющие
конструкции собираются из переходов; знаковая арифметика и загрузки
16/32-бит собираются из беззнаковых кирпичей.

DoD: «hello» и вложенные вычисления пишутся словами; минимальный
стандартный словарь; тесты словаря.

ЭТАП 4 — САМОХОСТИНГ №1

Что: ассемблер и эмулятор UVM, написанные на uAsm/uBrick и исполняемые
на UVM (программа пишет себя сама).

DoD: Python-инструменты остаются лишь эталоном; ключевые тесты проходят
на самохостинговой связке.

ЭТАП 5 — УСТРОЙСТВА И РАСШИРЕНИЕ ISA (UVM v0.2+)

Что: шина устройств вместо SYS (консоль, блоки данных, таймер),
прерывания; при необходимости — защита памяти и многозадачность.

DoD: программа на uBrick читает/пишет устройство через шину, не через
SYS.

ЭТАП 6 — ULANG: ЯЗЫК ВЫСОКОГО УРОВНЯ

Что: типы, структуры, модули, обработка ошибок — поверх кирпичей;
компилятор написан на uBrick.

DoD: компилятор uLang компилирует сам себя (самохостинг №2).

ЭТАП 7 — ТРАНСЛЯЦИЯ EXE -> UADRO

Что: разбор PE/ELF, декодер машинных команд (по кирпичику на класс
команд), трансляция в uAsm/UVM.

DoD: тривиальная программа из реального EXE исполняется на UVM.

ЭТАП 8 — USTD: СТАНДАРТНАЯ БИБЛИОТЕКА

Что: память, строки, контейнеры, математика, файлы — только из
кирпичей.

DoD: библиотека закрывает потребности следующих этапов без внешнего
кода.

ЭТАП 9 — ГРАФИКА И ВОКСЕЛЬНЫЙ ДВИЖОК

Что: экран как устройство UVM, ввод, затем воксельный рендер.

DoD: вращающийся воксельный объект, управление с устройства ввода.

ЭТАП 10 — КЛОН MINECRAFT СОВРЕМЕННОЙ ВЕРСИИ

Что: мир, генерация, физика, инвентарь, крафт — по подсистемам, каждая
подсистема — отдельная ветвь этапа.

DoD: играбельный воксельный мир с базовым игровым циклом Minecraft.

ЭТАП 11 — ИНСТРУМЕНТЫ НЕОГРАНИЧЕННОЙ МОЩИ

Что: отладчик, профайлер, REPL, самоанализ — на собственной
инфраструктуре.

DoD: каждый инструмент сам исполняется на UVM и расширяется языком.

ГДЕ МЫ СЕЙЧАС

Этап 1 закрыт 2026-11-04: ядро UVM v0.1 полностью — состояние машины
и ловушки (t0.uvm.core), обработчики всех 38 опкодов (t0.uvm.ops),
таблица опкодов (t0.uvm.table), декодер (t0.uvm.decode), шаг
исполнения (t0.uvm.exec), цикл запуска (t0.uvm.run), запуск образа
из файла (t0.uvm.cli: python tools/uvm_cli.py ОБРАЗ.uvm [--ram N]
[--ds N] [--rs N], код UVM — в код выхода процесса) и
интеграционные программы «вывод символа» ("Hi"), «арифметика»
((2+3)*4), «вложенные CALL/RET» (глубина 2, "!") — t0.uvm.integration.
SPEC/L0-UVM.txt принят. Тесты покрывают каждую группу опкодов и
каждую ловушку 1-8; тест-набор дополнен кирпичами image_of,
image_file, FakeStream, patched_stdin, run_via_cli.

Этап 2 (uAsm) начат 2026-11-05: принята SPEC/L2-UASM.txt v0.1
(структура строк, имена и символы, литералы, инструкции, директивы
данных, порядок разбора строки, два прохода, сообщения об ошибках,
дизассемблер с раунд-трипом) и закрыты ветви этапа:

- t0.uasm.lex — кирпичи литералов uAsm (десятичные, шестнадцатеричные,
  двоичные и символьные числа с минусом, диапазон -2^63..2^64-1,
  имена ASCII, строковые литералы с escape и байтами UTF-8) с тестами
  всех форм и границ;
- t0.uasm.symbols — таблица символов: symbols_new, symbol_get,
  symbol_define; единое пространство имён меток и констант, ошибка
  «повторное определение имени X»;
- t0.uasm.line — разбор одной строки в запись: кирпичи
  find_outside_quotes, strip_comment, clean_line, find_eq, split_first,
  split_words и parse_line по порядку раздела 7 SPEC — записи
  label/const/instr/data либо ("error", текст), None для пустой строки
  и комментария; значения констант разбираются сразу, операнды
  инструкций и аргументы DB/DW остаются текстом до прохода 2;
- t0.uasm.encode — кодирование записей в байты: to_word (отрицательные
  значения оборачиваются по модулю 2^64), word_le (восемь байтов
  little-endian), byte_of (байт 0..255), resolve_value (операнд —
  числовой литерал или имя из таблицы символов; значение имени —
  как есть, оборачивание при кодировании), encode_instr (опкод;
  у PUSH/PICK/JMP/JZ/JNZ/CALL/HALT/SYS — поле imm64 little-endian),
  encode_db/encode_dw (байты и слова директив), record_size (размер
  записи для адресов прохода 1), encode_record (запись целиком — вход
  прохода 2; DS/DZ проходят насквозь, метки и константы байтов
  не дают).
- t0.uasm.assemble — сборка текста в образ двумя проходами: split_lines
  (деление текста на строки, концевые CR снимаются — текст CRLF
  собирается как LF), wrap_error («uAsm: строка N: текст»),
  define_symbol (метка — адрес следующей записи, константа — значение),
  pass1 (разбор строк в записи parse_line, адреса по record_size,
  таблица символов; первая ошибка прекращает проход), pass2 (кодирование
  записей encode_record с подстановкой имён — ссылки вперёд разрешены
  проходом 1), assemble (текст -> образ; пустой текст — пустой образ).

Следующий малый шаг: Этап 2, ветвь t0.uasm.disasm — дизассемблер
образа (SPEC/L2-UASM.txt, раздел 8): линейное чтение с адреса 0,
по одной инструкции на строку («МНЕМОНИКА» или «МНЕМОНИКА значение»,
значения — десятичные литералы, имена не восстанавливаются); останов
декодирования — неизвестный опкод или поле imm64 за границей образа,
хвост данных печатается директивами DB до восьми аргументов на строку;
пустой образ — пустой текст. Раунд-трип assemble(disasm(B)) == B
остаётся критерием готовности этапа (ветвь t0.uasm.integration).

Контракт обработчиков (действует, реализован в t0.uvm.decode/exec):
к моменту вызова обработчика PC уже указывает на байт, следующий
за инструкцией целиком (включая поле imm64); обработчики переходов
переписывают m.pc сами; HALT поднимает UvmHalt с кодом imm по модулю
256; ловушки остаются UvmTrap.
